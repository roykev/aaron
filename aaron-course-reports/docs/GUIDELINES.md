# דוח פדגוגי מרוכז לקורס: הנחיות ותהליך

החבילה מייצרת דוח HTML אחד לקורס, מתוך דוחות Teaching Snapshot שבועיים של Aaron. הדוח כולל עמוד ראשי של סיכום הקורס ועמוד לכל שיעור.

## קבצים

המסמך הזה מתאר את כללי התוכן והעיצוב. הקוד, הקלטים והפקודות מתוארים ב-`README.md` וב-`AGENT_TASK.md` שבשורש החבילה.

## שלושה דוחות לקורס

כשיש נתונים, הדף הוא מרכז קורס עם ארבעה חלקים, וניווט קבוע בראש העמוד:

| חלק | מקור | מה מוצג |
| --- | --- | --- |
| סקירה | `analysis.json` ‏(`hub`) | hero, שלוש קופסאות עם 2 עד 3 עיקרים וקישור לכל דוח, תובנות "כוונה מול תוצאה" שמחברות את הדוחות, וציר שיעורים |
| מה לימדתי | `lecturer_report` בייצוא (Class Analysis) | יחידות הקורס, חלוקת זמן בכל שיעור, מעורבות בכיתה לפי סוג, נושאים מאתגרים |
| איך לימדתי | `snapshot_report` בייצוא | הדוח הפדגוגי: 16 הממדים, המלצות הינשוף ואימוצן |
| מה למדו | קובץ דוח הלמידה (`--learned`) | הדוח מוצג בדיוק כפי שהתקבל, בתוכן ובעיצוב שלו. הנתונים המפורקים ממנו משמשים רק לחיבורים: ציוני שיעורים בציר הקורס ובעמודי השיעורים |

- כותרת הסקירה: שם הקורס, ומתחתיו "דוח מרצה מלא". הפסקה הראשית (`sub`) חיובית ומשלבת את שלושת הדוחות: מה נלמד, איך, ומה נקלט. דוח הלמידה הוא רק חלק ממנה.
- שלוש התיבות בסקירה: תובנה אחת כמשפט (`insight`) ושתי "פתיחות" קצרות (`points`) שמזמינות לעבור לדוח המלא, עם קריאה לפעולה (`cta`). מעט מספרים.
- עיצוב אחיד לשלושת הדוחות: ערכת צבעים בהירה אחת, לפי דוח הלמידה (slate, teal, amber, blue), וגופן Heebo בכל הדף.
- "מה לימדתי": חלוקת זמן ותתי-נושאים לפי יחידה (תרשימי עוגה), ושורה אחת לכל שיעור עם מספר האינטראקציות והשאלות. הפירוט נמצא בעמוד השיעור.
- "מה למדו" כולל את כרטיסי הסטודנטים כפי שהם בדוח המקורי. לשיתוף מחוץ לצוות ההוראה, להסיר אותם מקובץ המקור.
- תובנות "כוונה מול תוצאה" הן מתאם תצפיתי. לציין כמה שיעורים עומדים מאחורי כל טענה.
- בלי `hub` ובלי נתוני "מה לימדתי" ו"מה למדו", הדף מציג רק את "איך לימדתי".

## התהליך לקורס חדש

1. **לאסוף קלטים:** ייצוא JSON של השיעורים מ-Aaron, ואם קיים גם דוח הלמידה (MD), וקובץ `course.json` עם שם הקורס.
2. **לבנות:** `course-reports build --reports export.json --learned learning_report.md --course course.json --out out/ --format both`.
   הניתוח (מיפוי לממדים, המלצות חוזרות, אימוץ, יחידות) מחושב בקוד. הניסוח נכתב בקריאה אחת למודל שפה, ובלי מפתח API נכתב ניסוח קבוע.
3. **לבדוק:** לקרוא את הדוח, ולתקן את `out/<slug>.analysis.json` לפי הצורך.
4. **לרנדר מחדש:** `course-reports build ... --analysis out/<slug>.analysis.json`.

## הנחיות תוכן

**טון ושפה**
- ה-hero חיובי: משפט אחד שמתאר את מה שהמרצה עושה הכי טוב, ומשפט שמסמן את הצעד הבא.
- 3 עד 5 תובנות. כל תובנה: כותרת קצרה ומשפט אחד עם עוגן לשיעור ספציפי.
- שפה תצפיתית: "נצפה", "עלה בדוח". אימוץ המלצה הוא מתאם תצפיתי, לא הוכחה שההמלצה גרמה לשינוי.
- בלי מקפים ארוכים (—), בלי מבנה "לא X אלא Y".
- בדוח שיוצא החוצה: בלי שם מוסד.

**מיתוג AaronOwl**
- חותמת עגולה של AaronOwl מופיעה ב-hero, ליד שלוש סקציות ההמלצות ובכותרת התחתונה.
- ההמלצות מוצגות כהמלצות של הינשוף, לדוגמה: "אילו המלצות של הינשוף אומצו בפועל?", "ההמלצות שהינשוף חזר עליהן הכי הרבה", "מה הינשוף ממליץ להמשך".
- צבעי החותמת: navy ‏`#0C2460` ו-ice ‏`#CADCFC`.

**מבנה העמוד הראשי (בסדר הזה)**
1. Hero.
2. תובנות.
3. קוביות סיכום עם קישור לסקציות: המלצות חוזרות, המלצות שאומצו, ממדי שיפור, המלצות להמשך.
4. מפת 16 הממדים.
5. המלצות חוזרות: שלוש המובילות, השאר בהרחבה.
6. המלצות שאומצו: רשימה של המלצה וסטטוס. העדות והשיעורים מופיעים רק בהרחבה.
7. ממדי שיפור: שם הממד בלבד. לפני ואחרי מופיעים רק בהרחבה.
8. המלצות להמשך: 3 שינויים קבועים, עם זמן בדקות.
9. אינדקס השיעורים.

**מפת הממדים**
- 3 קטגוריות, 16 ממדים, אריח לכל ממד.
- כל פריט בדוחות ממופה ל-1 עד 2 ממדים (`item_dims`). פרקטיקה או ביצוע בולט נספרים כחוזקה, הזדמנות לשיפור נספרת כשיפור.
- מיקום הממד: +1 לכל שיעור שבו נצפה כחוזקה, ו-1- לכל שיעור שבו הומלץ שיפור. **לא מציגים את הציון.** מציגים רק צבע (5 דרגות, מ"מוקד לשיפור" עד "חוזקה בולטת") ונקודה על פס.
- חץ ↑ מופיע כשהומלץ שיפור בממד, והשיעור האחרון שבו הממד עלה מסמן אותו כחוזקה.
- הפירוט לפי שיעורים מופיע רק כשפותחים אריח.
- לכל ממד יש `note` (2 עד 3 משפטים: מה נצפה, ואם צריך, איזה שיפור) ו-`focus` (תתי-ממדים מתוך `dimensions.json`).

**עמוד שיעור**
- קוביות: ביצוע בולט, פרקטיקות, הזדמנויות, פעולות.
- השיעור על מפת 16 הממדים, כתגיות צבועות.
- פרקטיקות והזדמנויות מוצגות ככותרות. הפירוט מופיע בהרחבה.
- פעולות מומלצות עם דרגת קושי.

## analysis.json, שדות

| שדה | תוכן |
| --- | --- |
| `course` | `name`, `title` (שם הדף, 2 עד 4 מילים), `description` |
| `hero` | `eyebrow`, `h1`, `sub` |
| `insights` | 3 עד 5 פריטים של `{title, text}` |
| `recs` | `{name, lessons, note}` לפי שכיחות, מהגבוהה לנמוכה. `note` נדרש רק לשלוש הראשונות |
| `adopt` | `{rec, lessons, status, evidence}`. ‏`status` הוא אחד מ: `yes`, `part`, `no`, `unk` |
| `growth` | `{dim, before, after, confidence}` |
| `next` | 3 פריטים של `{time, title, text}`. ‏`next_minutes` הוא סך הדקות |
| `dims` | לכל מזהה ממד: `{note, focus}` |
| `item_dims` | מפתח פריט ← רשימת מזהי ממדים |
| `hub` | אופציונלי: `eyebrow`, `h1`, `sub`, `taught_lead`, `reports` (3 קופסאות: `id`, `kicker`, `title`, `big`, `text`, `points`), `links` (תובנות: `title`, `text`, `taught`, `how`, `learned`, `caveat`), `units` (`name`, `short`, `lessons`, `note`) |
| `partial` | אופציונלי: `{מספר שיעור: "מה חסר בדוח"}` |
